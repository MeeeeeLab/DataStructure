## 今日目标

- 用同一 `TicketQueue` 接口验收循环数组队列与链表队列。
- 用排队叫号场景验证 FIFO、查看队首、空队列和容量边界。
- 比较固定容量循环数组与动态链表的空间取舍。

## 核心理解

两种实现都维护同一抽象：新票号从队尾进入，柜台从队首叫号。循环数组用 `head` 和 `size` 计算尾部 `(head + size) % capacity`，避免搬移；链表用 `head`、`tail` 保持两端操作 O(1)，删除最后一个节点时必须同步清空 `tail`。

同一组验收测试可以传入两种实现。这既检查 FIFO 行为，也说明使用方不应依赖数组下标或链表节点等实现细节。

## 核心接口

```java
interface TicketQueue {
    void enqueue(String ticket);
    String dequeue();
    String peek();
    int size();
}
```

## 验收清单

1. 空队列 `dequeue` 与 `peek` 抛出 `NoSuchElementException`。
2. 空白票号被拒绝；单元素出队后 `size` 回到 0。
3. A、B、C 依次入队时必须依次出队。
4. 循环数组在出队后重新入队，验证下标回绕且不搬移旧元素。
5. 固定容量已满时抛出 `IllegalStateException`；链表队列不使用容量上限。

## 复杂度与取舍

两种实现的 `enqueue`、`dequeue`、`peek` 和 `size` 都是 O(1)。循环数组空间连续、容量固定；链表按需增加节点，但每个节点还保存引用。选择实现时要同时看容量约束和内存布局。
